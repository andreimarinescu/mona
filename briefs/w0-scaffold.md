## Build

1. **Layout** per D1:
   - `apps/api`: uv project, package `mona`.
   - `apps/web`: Vite React app.
   - Root `package.json` with npm workspaces.
   - `compose.yaml`, `Makefile`, `.github/workflows/ci.yml`.
   - `scripts/`.
   - Remove the top-level `worker/` directory.
   - Keep `design/`, `docs/`, `briefs/` and `deploy/hermes/SOUL.md` as they are.
2. **API (`apps/api`):**
   - Python 3.12; pin current stable versions in `pyproject.toml` + `uv.lock`: FastAPI, pydantic-settings, SQLAlchemy 2 async with psycopg 3, Alembic, Procrastinate 3.x, pydantic-ai-slim with the openai extra, `fastmcp`, httpx, typer, pytest, pytest-asyncio, ruff.
   - Settings from env: `DATABASE_URL`, `MONA_ENV` (dev|prod), `MONA_DATA_DIR` (default `/data`), `MONA_SERVICE_KEY`, `OPENROUTER_API_KEY`, `MONA_OWNER_PASSWORD`, `HERMES_API_KEY`.
   - `GET /api/health` → `{status, db, version}`. The version comes from the package, and `db` is a real `SELECT 1`.
   - Alembic baseline migration: create extensions `unaccent` and `pg_trgm`, no domain tables (C1 isn't frozen).
   - Procrastinate app wired to the same database, its schema applied by the migrate step, and a `ping` task on each of the queues `llm` and `cpu`.
   - A Typer CLI entry point `mona` (`[project.scripts]`) with `mona version`. `doctor` and `demo-reset` come later.
   - An OpenAPI export command that writes `apps/api/openapi.json` without a running server.
3. **Web (`apps/web`):**
   - Vite + React 19 + TypeScript strict, TanStack Router (code-based routes are fine) + TanStack Query, react-i18next with `src/i18n/{en,fr,ro}.json`, Tailwind v4 **without preflight**, vitest + Testing Library, eslint (flat config).
   - `<html lang="en" data-theme="light">`.
   - Vite `server.fs.allow` includes the repo `design/` directory. The dev proxy sends `/api` and `/mcp` to `MONA_API_URL` (default `http://localhost:8765`, `http://api:8765` in compose).
   - A typed API client generated from `apps/api/openapi.json` with `openapi-typescript` + `openapi-fetch` (`npm run gen:api`). The generated file is committed, and CI fails if it's stale.
   - CSS load order in the entry: `design/mona-handoff/tokens.css` → `design/mona-design-system/components/bundle.css` → `src/styles/app.css`. `app.css` uses Tailwind's theme and utilities layers only. Map Tailwind's colours, fonts, radii and shadows onto the DS CSS variables, so utilities never introduce raw values. Fonts come from the handoff folder (self-hosted, never Google).
4. **DS bundle shim** (`apps/web/src/ds/`, plan §9):
   - A `globals` module sets `window.React` and `window.ReactDOM` (react-dom and react-dom/client as the bundle needs).
   - The shim module imports `globals` first, then the IIFE `design/mona-design-system/components/bundle.js` as a side-effect import, then re-exports `window.Mona`'s components and `format`. Types come from `design/mona-design-system/components/index.d.ts`, the contract; don't restate them.
   - The bundle says "React 18". Check it against React 19: removed APIs such as `ReactDOM.render`, `findDOMNode`, string refs, or `defaultProps` on function components. Record any incompatibility with its workaround.
   - A dev-only route `/dev/ds` renders a sample of each component family, with no console errors or warnings: Button, Input, Select, StatusPill, ConfidenceMeter, Card, Dialog, Toast, MonaAvatar, Citation, Icon, CategoryIcon, Banner, Progress, Badge, Tag, Table, Menu.
5. **pdf.js** (plan §4, §9; HANDOFF §7):
   - Vendor the latest stable pdf.js **release zip** (`pdfjs-<version>-dist.zip` from github.com/mozilla/pdf.js releases; not legacy, not npm) into `apps/web/public/pdfjs/`.
   - Drop `*.map` files and the bundled sample PDF; keep the locales.
   - `scripts/vendor-pdfjs.sh <version>` reproduces it and checks the zip's sha256, which is recorded in `apps/web/public/pdfjs/VERSION` with the version.
   - A **synthetic** sample PDF (fictional URSSAF-style payment demand in French with an amount such as "1 284,00 €" and a due date; generated by a committed script, e.g. reportlab via `uv run --with`) under `apps/web/public/dev/`.
   - A dev route `/dev/pdf` embeds `/pdfjs/web/viewer.html?file=/dev/sample.pdf` same-origin in an iframe. It has two buttons that find a phrase: one via the `#search=…&phrase=true` hash, one via `PDFViewerApplication.eventBus.dispatch('find', …)` per HANDOFF §7.4.
6. **Playwright:** one e2e smoke spec for `/dev/pdf`. Both find paths must produce a highlighted match inside the iframe (`.textLayer .highlight`). A second spec loads `/dev/ds` and fails on any console error. This infrastructure is reused later for the `findQuery` fixture check.
7. **i18n check:** `scripts/i18n-check.mjs` fails when:
   - fr or ro lack a key that en has;
   - any locale has a key en lacks;
   - a literal `t('…')` / `i18nKey="…"` in `apps/web/src` isn't in en.
8. **Compose (`compose.yaml`, D1):**
   - Services: `postgres:17` (healthcheck, named volume), `migrate` (one-shot: alembic upgrade + procrastinate schema), `api` (uvicorn with reload, port 8765), `worker-llm` (`procrastinate worker --queues llm --concurrency 1`), `worker-cpu` (`--queues cpu --concurrency 3`), `web` (node:24, Vite dev server on 5173, node_modules in a named volume).
   - One Python `Dockerfile` for api and workers, with ocrmypdf, tesseract-ocr + fra/eng/ron, poppler-utils and img2pdf.
   - `./data` bind-mounted at `/data`. Host ports come from env with the D1 defaults.
   - No Hermes service: S1 adds it.
9. **CI + Makefile:** GitHub Actions jobs `web` (lint, typecheck, vitest, i18n check, API client freshness, build), `py` (`ruff check`, `ruff format --check`, pytest with a postgres:17 service) and `e2e` (Playwright chromium against `vite preview` or the dev server). `make check` runs the web and py checks locally; `make e2e` runs Playwright.
10. **README:** the root README gets a short "Develop" section: `make up`, `make check`, `make e2e`, and where secrets live.

## Acceptance (fresh output in the report)

- `docker compose -p mona-w0 up -d --build` → all services healthy or running; `migrate` exits 0.
- `curl localhost:8765/api/health` → `db: ok`.
- A `ping` task deferred to each queue is executed, as shown in the worker logs.
- `make check` passes. Then break one fr key, and separately one `t()` key, and show the i18n check failing each time.
- `make e2e` passes both specs. Break the find query and show the spec failing.
- `/dev/ds` renders without console errors (e2e).
- The pdf.js version and sha256 are recorded.
- Tear the stack down with `docker compose -p mona-w0 down` (keep volumes).

## Don't

- No domain tables, REST resources, MCP tools or screens: those are contract-driven (W1, L1–L3).
- No assistant-ui or `ai`; S5 adds them.
- No Hermes service or config.
- No dark theme or theme toggle, and no Tailwind preflight.
- No shadcn or other UI kit.
- No practice documents anywhere; the sample PDF is synthetic.
