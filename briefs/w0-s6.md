## Tests

1. **Model and providers.**
   - Look up `qwen/qwen3.6-35b-a3b` and the fallback `qwen/qwen3.5-35b-a3b` on `/api/v1/models`: supported parameters, context length, pricing.
   - Look up each model's `/endpoints` list: provider, quantization, supported parameters, max output.
   - Recommend a `provider` object for dev: `order`, `require_parameters: true`, `quantizations` fp8 or better, and the `allow_fallbacks` stance. Base it on which providers support both `response_format`/`structured_outputs` and `reasoning`.
2. **Thinking toggle.**
   - On the pinned providers, compare the default, `reasoning: {enabled: false}`, and whatever else OpenRouter documents for Qwen hybrid thinking (e.g. `reasoning.effort`). Measure reasoning tokens (usage), whether reasoning text is returned, and latency.
   - State which knob reliably turns thinking off.
   - Note what the llama-server equivalent is: per-request `chat_template_kwargs: {"enable_thinking": false}`, plan §3. The adapter has to support both.
3. **No-think json_schema classification (v2).**
   - Take 10 documents: the text of their first 2 pages via `pdftotext` on the PDFs in `~/DevFiles/mona-hq/100 PDF neclasificate/`, preferring ones with a text cache.
   - Run the v2 SYSTEM prompt + SCHEMA, strict json_schema, thinking off.
   - Report schema-valid count, latency p50/p95 and cost.
4. **Evidence variant (C5 preview).** The same 10 documents, sent as **page-delimited** text (`pdftotext -f N -l N` per page, with page markers), with an extended schema.
   - Schema: `entity_hint`, `category` (the v2 enum), `counterparty`, `doc_type`, `doc_date`, `period_start`, `period_end`, `amount` + `currency`, `due_date`, `addressee`. Each field is `{value, quote, page}` or null. Plus `confidence`.
   - Verify every quote: normalise whitespace (including U+00A0 and U+202F), case and diacritics, then substring-match on the stated page. Report the verification rate per field and the main failure causes: wrong page, paraphrase, OCR spacing.
   - Try a prompt tweak or two to raise the rate, and report what worked.
5. **pydantic-ai.** Run the same extended schema through pydantic-ai `NativeOutput` against OpenRouter (the OpenAI-compatible or OpenRouter provider).
   - Show how to pass `reasoning` and `provider` pins via model settings / `extra_body`.
   - Show that it validates. Note the pydantic-ai version.
6. **Two-pass debrief (plan §2.2).** Build a **synthetic** cluster of 6–8 uncertain documents as JSON summaries in the repo: fictional names; ambiguities like the same insurer covering two insured persons (personal vs business), a bank statement for an unknown account, a supplier that could belong to two entities.
   - **Pass 1:** thinking on, free-form analysis.
   - **Pass 2:** thinking off, json_schema → `{questions: InterviewQuestion[] (maxItems 7)}`. Each question has:
     - `text` in the UI locale;
     - `evidence` refs (`doc_id`, `quote`);
     - `affected_doc_ids`;
     - `impact`;
     - 2–3 `options`, each with a label and a `rule_draft`: `{kind: always|depends|ask, discriminator?, conditions[], action: {entity?, category?, subcategory?}}`;
     - a suggested option.
   - Wall time for pass 1 + pass 2 must be ≤ 60 s. Run it 3 times; report wall times and whether the questions are sensible.
   - Also run pass 2 **with thinking on** + json_schema once and record what comes back. This documents the P0-3 failure mode (or its absence).
7. **Streaming latency.** Time to first reasoning token and to first content token for a short chat prompt, with thinking on and off.
